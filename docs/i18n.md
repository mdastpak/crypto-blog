# Languages, direction, and theme

The work of [#2](https://github.com/mdastpak/crypto-blog/issues/2). It follows the backend's rules ([Crypto-Exchange docs/i18n.md](https://github.com/mdastpak/Crypto-Exchange/blob/main/docs/i18n.md)), so a visitor gets the same language from the blog and from the API.

## Locales

- The locales this build has catalogs for are `AVAILABLE_LOCALES` in `apps/web/src/i18n/locales.ts` (`fa`, `en`).
- A release serves some of them, set by `LOCALES` (comma-separated, in the order of the switcher). By default an Iranian release (`DEPLOYMENT_REGION=ir`) serves `fa,en` and an international one `en,fa`.
- `DEFAULT_LOCALE` is the locale of a visitor whose languages match none; it defaults to the region's language (`fa` or `en`) when served, else the first of `LOCALES`.
- A value in `LOCALES` without a catalog, or a `DEFAULT_LOCALE` not in `LOCALES`, stops the server at start-up.

## URLs and the choice of locale

Every page lives under its locale: `/fa/...`, `/en/...`. A path without one (`/`, `/coins`) is redirected (`307`) by `src/proxy.ts` to the visitor's locale, chosen in this order:

1. The `locale` cookie: the visitor's choice in the switcher. The backend reads the same cookie.
2. `Accept-Language`, best quality first; a tag finds the locale of its language when its region is not listed (`fa-AF` finds `fa`).
3. `DEFAULT_LOCALE`.

A value that names no served locale is skipped, never an error. The redirect carries `Vary: Accept-Language, Cookie` and `Cache-Control: private, no-store`, so a shared cache never serves one visitor's language to another. The localized pages themselves are the same for everyone and are cached.

A locale the release does not serve, and any path no page matches, answers the localized 404 page.

## Direction

`<html lang dir>` follows the locale. The direction comes from the script of the language, like the backend: Arabic, Hebrew, Thaana, Syriac, N'Ko, Adlam, Hanifi Rohingya, Mandaic, Samaritan, and Mende Kikakui are RTL (`fa`, `ar`, `he`, `ur`, `ps`, `ckb`, `az-Arab`), every other LTR.

Layout uses logical CSS only (`ms-*`, `pe-*`, `start-*`, `text-start`), so one stylesheet serves both directions.

## Messages

- Catalogs are `apps/web/src/i18n/messages/<locale>.json`, keyed by stable SCREAMING_SNAKE keys, like the backend. English is the reference: tests fail when a locale misses a key, has an extra one, has an empty message, or uses other placeholders.
- `createTranslator(locale)` returns `t(key, params)`. Parameters are named (`{date}`) and may appear anywhere. In an RTL locale every value is wrapped in Unicode isolates (U+2068, U+2069), so that `BTC/USDT`, an address, or a number keeps its own direction inside Persian text. A missing parameter stays visible as `{name}`.
- To add a language: add its catalog, add it to `AVAILABLE_LOCALES` and `LOCALE_NAMES`, and list it in `LOCALES`.

## Numbers and dates

`src/i18n/format.ts` wraps `Intl`:

- Persian uses `fa-IR`: Persian digits and separators (`۱٬۲۳۴٫۵`).
- `formatPercentChange` signs changes (`+1.23%`).
- `formatPrice` shows ISO 4217 currencies with their symbol (`$64,250.50`) and other quotes with their code (`1.5 USDT`, `0.00001235 BTC`); values under 1 keep 4 significant digits.
- `formatDate` shows `fa` in the Persian (Jalali) calendar and `en` in the Gregorian one by default; `calendar` overrides it.

## Fonts

Self-hosted from npm (no request to a font CDN): Vazirmatn for Persian, Inter for Latin. Persian pages use Vazirmatn through `:lang(fa)`.

## Theme

`light`, `dark`, or `system` (the default, following `prefers-color-scheme`), the same values as `users.theme` in the backend profile.

- The choice is kept in the `theme` cookie (`system` deletes it).
- A small script in `<head>` sets `data-theme` on `<html>` before the first paint, so the page never flashes in the wrong theme, and the server needs no cookie, so pages stay cacheable.
- CSS reads `data-theme`, and `prefers-color-scheme` when there is none. Tailwind's `dark:` variant follows both.
- Following the signed-in user's saved theme comes with sign-in on the blog.
